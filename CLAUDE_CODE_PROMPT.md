## 1. Что такое Holescope
Приложение для водителей Ташкента: телефон в машине фоном читает акселерометр, гироскоп и GPS, находит ямы, неровности, люки, «лежачие», рельсы, оценивает ровность дороги и качество подвески машины, отправляет данные на сервер. Сервер («Мозг») объединяет проезды многих машин, учится на ответах водителей и строит карту качества дорог. Водителю: предупреждения «яма через 150 м, снизьте до 30 км/ч» (режим «контракам» — без маршрута, как предупреждения о камерах). Позже: рейтинг улиц, жалобы в Xalq Nazorati, маршрут «самый ровный».
Масштаб: Ташкент → область → Узбекистан → Таджикистан, Казахстан, Кыргызстан.

## 4. Ключевые факты из данных (не переоткрывай, но проверяй)
- Датчик ≈59 Гц, GPS ±3 м. Порог приложения 15 м/с² был слишком высоким (1 авто-кандидат против 21). Теперь: адаптивный `max(2.0, 4 × фоновый шум за 21 с)`.
- Ямы на скорости <10 км/ч почти не видны → поправка на скорость `score = peak / (v/40км/ч)^0.8` (α подбирается по повторным проездам).
- Положение ямы повторяется между проездами, амплитуда — нет → сервер подтверждает по месту (кластер 12 м + направление), силу берёт как медиану.
- На разметке 16.10 (61 из 91 сопоставлено): яма/не-яма точность 79%, полнота 89%; **уровни ям и типы (яма/лежачий/люк) по правилам не разделяются** — нужна разметка и модель. Это главный источник улучшений: активное обучение из приложения.
- Индекс подвески: основной — относительный (RI машины к медиане RI на тех же сегментах); абсолютный f_body/ζ с одного телефона на сиденье ненадёжен (резонанс телефона).
- Классы ровности A–E сейчас стартовые, калибровать по городу.

2. `python manage.py makemigrations fleet roadnet telemetry brain` → `migrate` → `createsuperuser` → `load_cars`.
3. Исправь всё, что упадёт (код ещё не запускался). Добавь тесты `pytest-django` на: регистрацию устройства, загрузку поездки, кластеризацию (два проезда → один кластер, 2 устройства → `confirmed`), `drive/ahead`, ответ на вопрос.

Критерий готовности: `pytest` зелёный, сервер стартует, админка Django открывается, API из таблицы в `backend/README.md` отвечает.

2. Тема: тёмная, светлая, системная — токены из Figma (для светлой темы нарисуй палитру и согласуй: те же акценты, инвертированные поверхности, контраст ≥ 4.5:1).
3. Локализация: **узбекский (латиница) и русский**, переключатель в настройках, по умолчанию язык системы.
4. Экраны из Figma (версии v0.2–v1.3): Разрешения, Поездка (Drive), Моя карта, Живая карта, Карточка ямы, Профиль, Настройки, Предупреждение (HUD), Жалоба, Рейтинг улиц, Статус жалобы, Выбор маршрута, Уведомления, Дашборд города, Челленджи, Отчёт недели. Реализуй через `get_design_context` для каждого фрейма, переиспользуя компоненты (Chip, Button, Pin, List item, Tab bar).
5. **Загрузочный экран-анимация (3 с):** логотип-прицел; прицел скользит по тёмной карте (тонкие линии улиц), «ловит» точки-ямы, они вспыхивают красным и «захлопываются» в центральный прицел → лого Holescope. Реализовать на `CustomPainter` + `AnimationController`, 60 fps, без видео. Сделай вариант `reduce motion`.
6. Новые экраны (нарисовать в Figma через MCP, затем сверстать): Профиль машины и подвески (модель, колёсная база, шины, давление, индекс S1–S5, график изменения), Вопрос «что это было?» (волна удара, 4–6 кнопок, «не знаю»), Итоги поездки, Выбор положения телефона (сиденье / подстаканник / держатель), Роль (водитель / пассажир).
Критерий: все экраны открываются на Android и iOS, снимки совпадают с Figma, ru/uz и обе темы работают.

### Этап 2 — фоновая запись и алгоритм на устройстве
1. Фоновый сервис: Android — foreground service с уведомлением «Holescope записывает дорогу»; iOS — `UIBackgroundModes: location` + CoreMotion; разрешения с понятным онбордингом. Экономия батареи: датчики на полной частоте только при движении >10 км/ч.
2. **Авто-поездки** (порт `holescope_algo/trip_state.py` в Dart): старт ≥15 км/ч 20 с (или activity=automotive); стоп <3 км/ч >3 мин, либо стоим >45 с и activity=walking (водитель вышел), либо потеря сигнала >5 мин; обрезка последней минуты простоя; кнопка ручного старта/стопа/«не записывать». Роли: водитель / пассажир (такси) / исследовательский. Не-авто режимы (пешком, автобус/трамвай) не отправлять в карту ям.
3. **Алгоритм v2 на устройстве** (порт `signal.py`, `detector.py`, `classify.py`, `roughness.py` в Dart): оси авто по GPS, адаптивный порог, поправка на скорость, признаки формы (колёсная база из профиля), ровность по сегментам 50 м (классы A–E), индекс подвески. Тесты на Dart: загрузи CSV из `analysis/` и сравни события с выводом Python (допуск по времени 0.1 с, по пику 5%).
4. Предупреждения «впереди яма»: запрос `GET /drive/ahead` по GPS+heading (кэш + офлайн по скачанному району), голос (`flutter_tts`, ru/uz) и звук, настраиваемая дистанция 100–300 м, без повторов одной ямы.
5. Офлайн-очередь (drift/isar): события и сегменты копятся и уходят пачкой (`POST /trips`) при сети; повтор с backoff; сырой CSV только для исследовательских устройств (gzip).
6. После поездки — до 5 вопросов «что это было?» (`GET /questions/next` → ответ → `POST /questions/{id}/answer`).
Критерий: запись идёт при заблокированном экране 30+ минут на реальных Android и iPhone; авто-старт/стоп отрабатывают; результаты Dart совпадают с Python на двух CSV.

### Этап 3 — бэкенд: умнее и точнее
1. Привязка к дорожному графу: импорт OSM Ташкента (`highway`, `surface`, `maxspeed`, трамвай, `railway=level_crossing`), нарезка на сегменты 50 м, ID вида `R01-0412` (см. `HOLESCOPE_V2.md`, §4), классы R/A/B/C/D/S, районы (12 районов Ташкента) и махалли (проверь доступные источники границ; если нет — заведи как TODO с планом получения).
2. Map matching (Valhalla Meili) → события и сегменты привязываются к `Segment`; пересчёт `ri_median` по сегменту всеми машинами; **относительный индекс подвески** по формуле из `holescope_algo/suspension.py` (минимум 3 машины на сегмент, пересчёт каждые 25 км).
3. «Заделана»: тихие проезды мимо кластера (уже есть `mark_quiet_pass`) вызывать из приёма поездки; учесть время и число устройств.
4. Калибровка устройства по «известным ориентирам» (люки, рельсы) → `calib_gain`.
5. Обучение: импорт `labels_*.json` в `Label`, команда `train_brain`; включение новой версии только если метрики на отложенных поездках лучше; переобработка старых событий новой версией; ночные задачи (Celery или cron + management commands).
6. Антиспам и доверие: `trust` устройства, отсев нереалистичных скоростей/мест, лимиты.
7. Публичные эндпоинты: карта, рейтинг улиц/районов, отчёт недели. Документация OpenAPI (drf-spectacular или ручная).
8. Автоопределение модели авто — только каркас (отпечаток + k ближайших), включать при данных; сейчас — выбор в профиле.
9. Достижения (идея на потом, оставь модель-заготовку): «самая мягкая машина недели/месяца/года» по медиане `softness_score` на модель (≥10 машин и ≥500 км на модель).

### Этап 4 — админка (отдельное веб-приложение `admin-web/`)
Только русский. Стек: Vite + React + TypeScript, Tailwind, MapLibre, react-three-fiber (Three.js), framer-motion; тёмная тема в фирменных цветах (+ светлая). Сначала нарисуй ключевые экраны в Figma (MCP), потом верстай точь-в-точь.
Разделы: Обзор (KPI, активность), Карта (слои: ямы по типам/уровням, ровность A–E, районы, махалли, плохие участки; фильтры), События (модерация: подтвердить/отклонить/объединить/сменить тип и уровень/добавить вручную), Дороги (реестр с ID, классами, покрытием), **Устройства** (список + карточка устройства: телефон, платформа, версия, роль, положение, калибровка, доверие, последняя активность, поездки; **редактирование машины и подвески**: модель, год, колёсная база, шины, давление, класс S1–S5), Поездки (волна + маршрут, перенос `review.html`), Справочники (все термины: типы, уровни, классы, покрытия, положения, статусы), Жалобы, Доступы (роли).
**Раздел «Мозг»:** 3D-визуализация (граф/облако: узлы = кластеры ям, дороги, версии алгоритма, признаки; связи = подтверждения; цвет = уверенность; можно вращать, приближать, кликать узел → карточка с историей и «памятью»), временная шкала обучения (метрики по версиям), очередь вопросов и разметки, ручная загрузка CSV (drag-and-drop → `POST /admin/brain/upload-csv` → отчёт и просмотр событий), редактор параметров алгоритма (`Params`) с предпросмотром на выбранной поездке, переключение активной версии.
Критерий: админка работает на реальных данных из БД, визуально совпадает с макетами, анимации плавные, раздел «Мозг» реально читает данные (не заглушки).
