# Holescope — план проекта: карта ям для водителей Ташкента

## Выбор стека

| Слой | Выбор | Почему | Запасной вариант |
|---|---|---|---|
| **Сбор данных (сейчас)** | Веб-страница на чистом JS (этот проект) | Работает на iPhone сразу: без Mac, без Apple Developer, без магазинов | — |
| **Мобильное приложение** | **Flutter** | Вы его знаете; один код под iOS и Android; есть плагины для датчиков, GPS и карт | Нативный Kotlin + Swift: лучше для фона, но две кодовые базы |
| Датчики и GPS | `sensors_plus`, `geolocator` | Стандартные плагины, активно поддерживаются | — |
| Работа в фоне | Android: foreground service (`flutter_foreground_task`); iOS: `UIBackgroundModes → location` | Без этого запись остановится при блокировке экрана | — |
| Карта | `flutter_map` или MapLibre + тайлы OpenStreetMap | Бесплатно для старта | Для продакшена — платный провайдер тайлов: публичные серверы OSM не рассчитаны на нагрузку |
| **Сервер** | **Supabase** (Postgres + PostGIS) | Геозапросы и кластеризация прямо в базе; анонимный вход из коробки; права доступа на уровне строк | Firebase: он вам знаком, но в Firestore нет нативных гео-запросов, и кластеризацию ям придётся писать самим |
| Обработка | Клиент: порог по скорости. Сервер: кластеризация (`ST_ClusterDBSCAN`) + подтверждения от разных устройств | Одна запись — это кандидат, яма — когда её «почувствовали» несколько телефонов | ML (TFLite) только если порога и формы сигнала не хватит |
| Анонимный ID | Анонимный вход Supabase → ник вида «Тихий Сокол #4821» | Копится репутация, но нет почты и телефона | — |

**Что понадобится для iOS-версии Flutter:** способ собирать iOS без Mac (облачная сборка, например Codemagic,
либо Mac) и Apple Developer Program (около $99 в год) для TestFlight. На Android проще: APK ставится напрямую.

## Этапы

| # | Этап | Критерий «готово» |
|---|---|---|
| 0 | **Сбор данных** (этот проект) | 3–5 поездок, от 30 ям и по 10 неровностей других типов; `analyze.py` запущен |
| 1 | **Алгоритм v1** | По данным подобран порог (с учётом скорости); на новой поездке проверено: доля найденных ям и число ложных срабатываний на километр |
| 2 | **Flutter-прототип** | Запись в фоне, определение ям на телефоне, отправка событий на Supabase, карта |
| 3 | **Подтверждения** | Кластеризация; отметки «на месте» / «заделана»; голосовое предупреждение за 100–200 м |
| 4 | **Пилот** | Один район или 5–10 главных улиц; 10–20 водителей (знакомые, чаты такси) |
| 5 | **Давление и охват** | Жалоба в один клик (Xalq Nazorati, платформа Минтранса), рейтинг худших улиц, Instagram с цепочкой «нашли → подали → исправили» |

Деньги и пожертвования откладываем: юридически это сложно, а суммы несоизмеримы с бюджетом на дороги.

## Риски и решения

| Риск | Что делаем |
|---|---|
| Веб-страница не читает датчики в фоне на iPhone | Только для сбора данных; продукт — нативное приложение |
| Телефон лежит по-разному, машины разные | В логгере есть поля «автомобиль» и «положение»; порог зависит от скорости; данные собираем с разных машин |
| Ложные срабатывания: люки, рельсы, «лежачие», стыки | Метки типов в логгере → различаем по форме сигнала; подтверждение от нескольких устройств |
| GPS в городе ошибается на 5–10 м | Кластеры в радиусе около 10–15 м; привязка к улице (map matching) |
| Батарея | Запись только при скорости выше ~10 км/ч; умеренная частота датчиков |
| Приватность | Храним точки событий, а не маршруты; анонимные ID; политика конфиденциальности |
| Пустая карта в начале | Один район; сами проезжаем главные улицы до запуска |
| Безопасность за рулём | Никакого ввода на ходу: пассивный режим, одно касание или голос |
| Государство запустит своё | Встраиваемся в официальные каналы (жалоба в один клик), а не конкурируем с ними |

## Что делать дальше

1. Выложить страницу по HTTPS и поставить на iPhone (см. README).
2. Сделать 3–5 поездок и прислать CSV-файлы.
3. Вместе посмотрим график и подберём алгоритм (этап 1).
4. Когда увидим, что ямы различимы, делаем Flutter-прототип.
